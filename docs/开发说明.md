| **security.py** | token 鉴权 + 日志/响应脱敏 | `TOKEN_FILE`（data/token.txt，首启自动生成）；`get_token/check_request`（L25-50）；`sanitize/sanitize_dict`（L52-63） |

| **logging_setup.py** | 系统日志（RotatingFileHandler 5MB×5，UTF-8） | `setup_logging()`（L55）；`attach_task_id`（L32）；所有日志内容强制过 sanitize |

## 2. 数据流（上传 → 任务 → 引擎 → 输出）

```
浏览器上传                    服务端处理
──────────                   ──────────
1. POST /api/configs/upload  → configs.save_config → data/configs/<type>/<name>_v<N>.xlsx
2. POST /api/uploads         → files_store.save_order_file → data/uploads/清洗名_时间戳.ext
3. POST /api/jobs            → task_manager.submit_job:
      ├─ 校验 cookie 非空 / order_files≥1 / 必填配置齐全（configs.resolve_configs）
      ├─ files_store.snapshot_inputs → data/tasks/<id>/inputs/（订单+配置副本，删源不影响）
      ├─ db.create_task(pending)     → SQLite tasks 表
      └─ executor.submit(run_job)    （ThreadPoolExecutor(2)，pending 数 >10 拒绝"服务忙"）
4. run_job（线程内）        → pending→running
      ├─ ProfitEngine.process(快照路径, cookie, thread_count, enable_tax, exclude_ids, outputs/<id>/)
      ├─ 引擎内线程池并发查菜鸟 API（get_charge_order_list，命中 tax_cache 免查）
      ├─ 回调：log_cb→db.append_log（内存 deque 由 SQLite log_json 承担）；progress_cb→update_task
      ├─ 生成 {日期}全店铺销售数据汇总表.xlsx（原表/处理表/推广表/全店汇总/销售计划/每日数据）
      └─ 成功→done + result_files_json；异常→error（错误信息落库，traceback 不回流前端）
5. 任务结束           → tax_cache.force_flush（全局缓存合并落盘）→ stats.record_task_finish
6. 前端 2s 轮询       → GET /api/jobs/<id>?since=N（增量日志，seq 去重）
7. 下载               → GET /api/jobs/<id>/download/<file>（send_from_directory，done 才可下）
8. 清理               → 手动 DELETE 任务；启动时 cleanup_outputs 清 >24h；孤儿上传 7 天 TTL
```

**关键不变量**：快照先行（任务与源文件隔离）；输出写完才置 done；缓存全局共享但原子落盘；重启时 running/pending 一律置 error（"进程中断"）。

## 3. 如何跑测试

### 3.1 pytest 全量（根目录 tests/）
```bat
:: 在项目根目录（tests/conftest.py 已把 profit_service/ 加入 sys.path，fixtures 由 fixtures_gen.py 动态生成）
python -m pytest tests/ -q
```
覆盖：`test_engine_utils.py`（工具方法）、`test_engine_loaders.py`（5 个 load_*）、`test_api_configs.py` / `test_api_jobs.py`（Flask test_client 全链路，monkeypatch `engine.get_charge_order_list` 注入假响应）。
另有一份独立单测 `profit_service/tests/test_files_store.py`（files_store 的 sanitize/validate/CRUD/快照/清理），可用 `python -m pytest profit_service/tests -q` 单独跑，也可并入全量。

### 3.2 冒烟（smoke_test，e2e_smoke 现役版）
```bat
python tests/smoke_test.py
```
构造 fixture（成本/链接/推广/官补/排序 + 2 天订单 CSV）→ 用假 Cookie 完整跑 ProfitEngine → 断言：单日/多店铺/空输入报错/多天合并四类场景的 Excel 结构、sheet 顺序与数值手算一致（含 R2 多店铺计划表、R3a 空输入）。退出码非 0 即失败，输出到 `tests/_smoke_out/{single,multi,empty,multiday}/`。

### 3.3 性能测试（perf_test）
当前仓库**尚无 perf_test 脚本**。需要时按以下方式补（对齐 stats.py 已有指标）：
- 目标：验证大文件（如 2000+ 行订单 × 2 天）在 thread_count=2/4 下的耗时与 P95 查询延迟、缓存命中率（`data/stats.json`）
- 建议实现：`tests/perf_test.py`，复用 fixtures_gen 放大行数，mock `get_charge_order_list` 为固定延迟（如 0.2s）以模拟真实网络，输出耗时表，不设硬性断言（性能基准记录用）

### 3.4 引擎一致性对比（改引擎后必跑）
```bat
python tests/compare_workbooks.py a.xlsx b.xlsx
```
黄金样本双指针对比（sheet 名/顺序、值、公式规范化、样式），公式列外零容忍差异。

## 4. 如何加新功能 / 改引擎

### 4.1 流程（引擎改动是红线操作）
1. **先确认口径**：引擎任何行为变更都会改变输出 Excel，必须先与业务确认新口径（参考 `引擎已知问题清单.md` 附录 A——现有 4 项未修复问题就是"口径未定所以不动"的典型）
2. 在 `engine.py` 改代码：保持零 UI 依赖、回调注入、无全局可变状态
3. **标注**：差异点一律加 `# [Web版修复 xxx]` 注释（沿袭现有约定），并在模块 docstring 修复清单里补一行
4. **版本号**：engine.py 顶部 docstring 无独立版本常量，约定在文件头"修复清单"下追加 `- Vx.y: <变更摘要>` 行；涉及行为变更时同步在 `模块接口契约.md` 第 13 节与 `引擎已知问题清单.md` 附录 A 更新状态
5. **回归要求**（全绿才可提交）：
   - `python tests/smoke_test.py`（结构 + 数值手算断言）
   - `python -m pytest tests/ -q`（全量，新功能需补 fixture 与断言）
   - 与 GUI 双跑黄金样本对比：GUI 跑同一批输入 → `compare_workbooks.py` 零容忍（公式顺序容忍）
6. **服务层无感**：只要 `process()` 签名不变，task_manager/app 无需改动；若签名变了，同步更新 task_manager.run_job 与接口契约

### 4.2 加新功能（不改引擎时）
- 新 API：app.py 加路由 + 契约文档补一行 + test_api_*.py 补用例
- 新配置类型：configs.CONFIG_TYPES 注册（required/multiple 语义）→ 前端向导卡片 + validate_on_upload 表头契约
- 新统计指标：stats.py 加字段 + /api/stats 输出 + 文档

## 5. 已知限制（上线沟通口径）

| 项 | 值 | 说明 |
|---|---|---|
| 并发任务 | **2**（ThreadPoolExecutor max_workers=2） | 第 3 个起排队 |
| 排队上限 | **10** 个 pending | 超出返回"服务忙"（code 6），前端禁用提交按钮 |
| 结果保留 | **24h** | 启动时清扫超龄 outputs；也可手动 DELETE 任务 |
| 任务内并发 | thread_count 2~4（默认 2） | 菜鸟 API 限流：全局令牌桶 ≤2 QPS + 指数退避 + 熔断（R4） |
| 鉴权 | **单静态 token**（data/token.txt，首启生成，前端 localStorage 保存） | 无多用户/无角色；Cookie 明文仅服务端持有、日志脱敏 |
| 上传 | 单文件 ≤10MB，.csv/.xlsx 白名单 + 魔数 | 订单文件同名加时间戳永不覆盖；配置覆盖升版本保留 10 版 |
| 缓存 | tax_cache.json 全局共享 | 任务结束原子落盘；重启加载，缓存命中免查 API |
| 状态机 | pending→running→done/error（无 cancelled） | 引擎不可安全中断；重启时 running/pending 置 error |
| 平台 | Windows + Python 3.14 venv | waitress（gunicorn 不支持 Windows）；openpyxl 锁 3.1.x |

## 6. 常见排障速查

- 任务卡住 → `data/logs/app.log` 末条 traceback + `GET /api/jobs/<id>` 日志增量
- 风控/封禁 → 日志 grep `403|429`，核对限流与熔断日志
- Excel 结果与预期不符 → 先看 `引擎已知问题清单.md` 4 项已知行为（推广费 0、数量放大、订单重复计数、未知归并），再谈 bug
- 重启后任务全红 → 正常：中断任务置 error，结果目录已清理
- 中文文件名/内容乱码 → 检查是否绕过 files_store 直写路径（所有 open 必须显式 UTF-8/utf-8-sig）
