## 1. SKU 尾数 "-数字" 被误判为商品数量

| 项 | 内容 |
|---|---|
| 代码位置 | `engine.py:923-929`（处理表段）与 `engine.py:1499-1504`（每日数据段），两处重复实现；GUI 同源 `gui_batch_query.py:1093-1099` |
| 级别 | P2（静默算错，无任何报错提示） |

### 现象
```python
# 逻辑：取 SKU 最后一个 "-" 之后的部分，若全是数字则当作"规格件数"
if "-" in sku_key:
    suffix = sku_key.split("-")[-1]
    if suffix.isdigit():
        extracted_qty = int(suffix)
items_count = extracted_qty * res.get("qty", 1)
```
任何以 `-数字` 结尾的 SKU 都会被当作"一单含 N 件"，并乘上商品数量列得到 `实际商品数量`。

### 典型误判场景
- SKU 名包含年份/型号/批次：`XX-2026` → 尾数 `2026` 被当作件数，实际商品数量放大 2026 倍
- SKU 名含编码序号：`ABC-888`、`SKU-100` → 同理放大
- 规格名恰好以数字结尾的合法场景（如 `XX-2` 表示 2 件装）才"碰巧"正确

### 影响
- 处理表「实际商品数量」列数值爆炸 → 聚合汇总（商品数量/件数）与每日数据表全部失真
- 毛利润因综合成本 = 数量 × 单价而随之虚高（成本列会被放大）
- 无日志、无红行标记，只能人工核对数量才能发现

### 用户侧规避
- SKU/商家编码命名**避免以 `-数字` 结尾**（年份、序号放开头或改用下划线/字母，如 `2026-XX`、`ABC_888`）
- 确实以数字结尾的规格，确保「商品数量(件)」列不填或为 1，使放大倍数可控可预期

### 修复方向（未排期）
- 在 `engine.py` 中新增 `_extract_qty_from_sku(sku)` 统一两处（923、1499）逻辑，仅当尾数符合明确的规格件数语义（如 `-x2`、`-2件` 或与 SKU 主体强相关的模式）才推断，否则恒为 1
- 更彻底：废弃该推断，直接用订单「商品数量(件)」列（`res["qty"]`），SKU 只做展示
- 修改后需跑 smoke_test 的数值断言 + 与 GUI 双跑对比（黄金样本）

## 2. 推广报表日期格式不统一 → 推广费静默为 0

| 项 | 内容 |
|---|---|
| 代码位置 | `engine.py:161-170`（`parse_date`，加载推广表时逐行解析日期）→ `engine.py:401-420`（daily 键写入）→ `engine.py:840-845`（`get_promo` 按日取数）；GUI 同源 `gui_batch_query.py:996` |
| 级别 | P1（高频：手工维护的推广表日期格式五花八门） |

### 现象
- `parse_date` 只认 `2026-05-06` / `2026/05/06` / `2026年05月06日` 三种分隔（正则 `(\d{4})[-/年](\d{1,2})[-/月](\d{1,2})`）
- 推广报表日期写 `2026.5.6`（点号分隔）时解析失败 → `row_date_str` 退化为**原样字符串** `"2026.5.6"`，作为 daily 键存入 `promo_map[store][pid]["daily"]`
- 订单侧归属日期键是统一格式 `2026年05月06日`（`engine.py:406` 同款格式化）
- `get_promo`（`engine.py:840-845`）用订单日期键去 `daily.get(date_str, 0.0)` → **永远不命中 → 推广费 = 0**
- 单日文件命中 `daily.get(date_str)` 分支（845 行）；多天合并文件命中 sum 分支（843 行），同病

### 影响
- 销售计划登记表/全店汇总表/每日数据表的「推广花费」全为 0 → 毛利 = 销售额 − 成本 − 税运 − 扣点 + 推广费，推广费一侧完全缺失，**毛利偏高且失真**
- 无任何告警：推广表加载成功、条数正常，纯静默错配，极难发现

### 用户侧规避
- 推广报表内日期列**统一为 `2026-05-06` 或 `2026年05月06日`**（点号格式 `2026.5.6` 必踩坑）
- 批量导出推广数据后先做一次日期格式替换（Excel 查找替换 `.` → `-` 即可，注意月份/日不补零也兼容：`parse_date` 接受 `2026-5-6`）

### 修复方向（未排期，一行级修复）
- 让 `parse_date`（`engine.py:161-170`）把 `.` 也纳入分隔符：`s = str(date_val).replace('.', '/')` 后走正则——`parse_cost_date_range`（137-159）已支持点号（`s.replace('.','/')`），**两处行为对齐即可**
- 可选增强：`load_promo_map` 对解析失败的日期行打日志告警（当前 408 行静默保留原串），并统计"未匹配到标准日期"的条数
- 修改后回归：推广表用 `2026.5.6` 构造 fixture 断言 daily 键归一化

## 3. 同订单号多行 → 重复计数为多个订单

| 项 | 内容 |
|---|---|
| 代码位置 | 任务构建循环 `engine.py:609-680`（task_id 每行独立生成）；聚合 `engine.py:974`（store_agg `orders += 1`）与 `engine.py:991`（global_agg 同）；GUI 同源 `gui_batch_query.py:824、1144` |
| 级别 | P2（依赖源数据质量） |

### 现象
```python
if order_no:
    task_id = f"{row_date}_{store_name}_{len(rows)}"   # 按"行"编号，不按订单号
    ...
store_agg[p_name][p_id]["orders"] += 1                # 每行 +1，注释原文"按行计为订单数"
```
同一订单号在文件中出现 N 行（多 SKU 拆行、赠品行、或源系统重复导出）时：
- 每行独立成 task_id → **N 次菜鸟 API 查询**（浪费配额、放大风控面）
- 聚合时订单数 +N（真实应为 1）→ 订单数、件数、销售额口径全部虚高

### 影响
- 全店汇总/销售计划登记表/每日数据的「订单数量」失真
- 查询次数膨胀：与问题 4 叠加（未知店铺每单都查）时，API 调用量不可控
- 无法从结果表反推真实订单数

### 用户侧规避
- 上传前检查订单源文件：`订单号` 列应唯一，多 SKU 订单应合并为一行（商品数量列可大于 1，配合问题 1 的 SKU 尾数规则）
- 导出时用系统自带去重（按订单号保留一行）

### 修复方向（未排期）
- 任务构建循环（`engine.py:609-680`）以 `order_no` 为去重键：同订单号只建一个 task_id，其余行跳过查询但保留原表展示
- 聚合段（`engine.py:974/991`）改为按 task_id 的**订单号集合**计数（`len(seen_orders)`），而不是行累加
- 前置影响：处理表"一行一查询结果"的排版语义可能变化，需与业务方确认口径后再改

## 4. 未知店铺 / 未知产品静默归并

| 项 | 内容 |
|---|---|
| 代码位置 | `engine.py:192-197`（`extract_store_name` 无匹配返回 `"未知店铺"`）；`engine.py:963`（`p_name = store_link_map.get(p_id, "未知产品")`）；GUI 同源 `gui_batch_query.py:603、1134` |
| 级别 | P2（静默降级，数据仍出但归属错误） |

### 现象
- 订单文件名不含任何已知店铺（`KNOWN_STORES` = 庆余/雅丽丹/大咖猴/趣味猴/品味）→ 全部归入 `未知店铺` 一个桶，sheet 名 `未知店铺原表/处理表`，与其他店铺数据并列统计
- 链接汇总表中查不到该 `商品id` → 聚合键变成 `未知产品`，所有查不到的商品**合并成一行**
- 两者均无日志提示，属于"静默归并"

### 影响
- 多店铺文件（含未命名的新店铺）混入同一聚合桶 → 汇总表无法区分店铺口径
- 未知产品合并：不同商品的销售额/件数/成本堆叠在一行，毛利毫无意义且无法拆回
- 推广表按店铺加载（`load_promo_map` 以店铺名分组），`未知店铺` 的推广费必然查不到 → 与问题 2 叠加时毛利偏差更隐蔽

### 用户侧规避
- 订单文件**按 `店铺_日期.xlsx` 规范命名**（Web 前端上传向导已有此提示）
- 新店铺上线时：先更新链接汇总表（含新店铺名 + 全部商品 id），再上传订单
- 发现"未知"字样即停用结果，修正配置后重跑

### 修复方向（未排期）
- `extract_store_name`（`engine.py:192`）：无法识别时 log 告警（列出候选文件名与识别结果），后续可升级为 `EngineError`（Web 版上传预检处同步加店铺名识别提示）
- 聚合段（`engine.py:963`）：对 `未知产品` 分支打日志并统计条数；不改聚合结构但至少"可见"
- 依赖：R6 配置表契约校验（链接表表头完整性）落地后可进一步约束
